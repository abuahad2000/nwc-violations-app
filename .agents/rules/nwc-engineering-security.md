# نطاق — التنفيذ والأمان
فعّل هذه القاعدة Always On لهذا المشروع فقط. اقرأ docs/OPERATIONS_AR.md.

- نفّذ داخل apps/web: Next.js App Router، TypeScript strict، Tailwind CSS، shadcn/ui RTL، PostgreSQL/PostGIS، مصادقة وتخزين خاص. تحقق من الإصدارات الرسمية وثبت lockfile، ولا تفرض حزمًا تجريبية.
- لا كل الواجهة use client. افصل domain/data-access/auth/imports/reports عن العرض. runtime validation لكل مدخلات الخادم؛ TypeScript ليس مدقق ملفات Excel عند التشغيل.
- واجهة عربية مقروءة ومتجاوبة، وفلاتر موحدة، وصفحة لكل مقاول، ومهام حالية ذات سبب ومالك وموعد معلوم، وتفاصيل بلاغ وتصدير حقيقي. لا أزرار شكلية ولا أرقام hardcoded في الإنتاج.
- بيانات الاختبار معزولة وموسومة، لا fallback إليها عند عطل قاعدة أو شبكة. نقص الإعدادات يعلن بصراحة ولا يخفيه mock.
- المصادقة والتفويض لكل API/Server Action/RPC/تصدير/مرفق. RLS وgrants مناسبة، ولا أسرار في NEXT_PUBLIC أو client bundle أو Git أو logs.
- لا ملفات البيانات الخام في public أو مجلد ثابت لجذر المشروع. لا نشر للنسخة الحالية على debug=True. لا private cache مشتركة بين أصحاب الصلاحيات المختلفة.
- امنع XSS وXXE وZIP bombs وpath traversal وصيغ Excel المؤذية. تحقق من حجم الملفات ومصدرها وحقولها. لا NetworkLink تلقائي ولا أدوات خارجية لمعالجة البيانات دون إذن.
- لا نشر بيانات فعلية أو تفعيل تكلفة أو إرسال بريد أو تغيير DNS دون إذن صريح. Vercel Hobby ليس افتراضًا صالحًا لاستخدام تجاري. مكان الاستضافة يعتمد من الجهة المالكة للبيانات.
- مسار البريد: مسودة/مراجعة/اعتماد/إرسال مخول، والتغيير يلغي الاعتماد. سجل outbox وidempotency، ولا تزعم التسليم بمجرد قبول الطلب.
- اختبارات الوحدة والتكامل المكاني والصلاحيات وواجهة المستخدم ضرورية. شغّلها ثم انقل نتائجها الفعلية؛ successful build لا يثبت نجاحها.
- حافظ على تغييرات المستخدم وmigrations المطبقة، وحدّث أدلة docs عند تغيير التنظيم أو أوامر التشغيل. وثّق المعوقات ولا تدّع تنفيذًا أو قراءة أو نشرًا لم يحدث.
