# توحيد المقاولين

يحتفظ `contractors` بالاسم الموحد، ويحفظ `contractor_aliases` الأسماء البديلة المعتمدة. يبقى الاسم الأصلي في سجل البلاغ كما ورد في الملف، وتعرض القوائم والتصديرات الاسم الموحد؛ يحتوي Excel أيضًا عمود الاسم الأصلي للمراجعة.

لا تكفي مطابقة كلمة عامة أو حذف «شركة/مؤسسة» لدمج جهتين. يشمل التطبيع الآلي اختلافات الكتابة فقط، وتحتاج الاختصارات وتغيير الصفة القانونية إلى خطة مراجعة. الأسماء البديلة تُستخدم في استيراد المرجع وربط بلاغات المصدر، وتمنع إعادة تسمية مقاول باسم جهة أخرى أو باسمها البديل.

أداة `scripts/data/merge-contractors.ts` تقرأ خطة خاصة تحتوي source وtarget وsourceName وtargetName وreason وcanonicalName اختياريًا. التشغيل العادي يفحص الخطة؛ `--verify` يختبر المعاملة ويتراجع عنها؛ `--apply` يعتمدها. تُحفظ نسخة استرجاع محلية خاصة، وتُحدّث روابط المشاريع والبلاغات والمستخدمين والمهام داخل معاملة واحدة. لا تُعدّل نسخ المصدر التاريخية أو تُحذف البلاغات.

طبّق `004_contractor_aliases.sql` قبل نشر التطبيق على PostgreSQL. SQLite يجهز الجدول تلقائيًا. لا تضع خطة الدمج أو نسخ بيانات التشغيل في Git.
