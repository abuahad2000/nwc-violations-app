# دليل التشغيل والبيانات

## التشغيل المحلي

المتطلبات: Node.js24 أو أحدث وPostgreSQL مع امتداد PostGIS. التخزين التشغيلي الحالي SQLite محلي؛ PostGIS محرك التصنيف المكاني. على Windows يعتمد مشغل `start:local` الحالي على Ubuntu في WSL وعنقود PostgreSQL16؛ البيئات الأخرى تحتاج تشغيل خدمة PostGIS مسبقًا.

1. شغّل `npm run setup` لتثبيت الحزم المثبتة في ملف القفل.
2. انسخ `apps/web/.env.example` إلى `apps/web/.env.local` واضبط اتصال PostGIS.
3. للبيانات الموجودة: ضع نسخة قاعدة البيانات المحلية في `apps/web/data/nwc_local.db` أو اضبط `NWC_DATA_DIR` على مجلد البيانات الخاص. لا تضعها في Git.
4. شغّل `npm run build` ثم `npm start` وافتح `http://localhost:3100`.

عند التثبيت لأول مرة بدون قاعدة موجودة، أنشئ حساب الإدارة من `apps/web` بضبط متغيري البيئة `NWC_ADMIN_USERNAME` و`NWC_ADMIN_PASSWORD` ثم تشغيل:

```text
node --import tsx scripts/accounts/bootstrap-admin.ts
```

لا توجد كلمة مرور افتراضية في المستودع. أداة التهيئة ترفض استبدال الحسابات الموجودة. احذف متغير كلمة المرور من جلسة الطرفية بعد التهيئة.

## البيانات الخاصة

هذا المستودع يحتوي الكود والاختبارات الاصطناعية فقط. ملفات Excel وKMZ وJSON التشغيلية وقاعدة البيانات والنسخ الاحتياطية وملفات الاتصال تبقى في تخزين خاص. أدوات استيراد المرجع تقرأ الملفات المحلية من `excel/` و`kmz/` في جذر المشروع، وتولد المراجعة داخل `apps/web/data/`؛ إعداد هذه الملفات مطلوب قبل المزامنة المكانية.

بعد استكمال بيانات Excel وKMZ الخاصة يمكن تشغيل `npm --prefix apps/web run reference:prepare` ثم مراجعة واعتماد المرجع من التطبيق. لا تُشغّل اعتمادًا آليًا على مرجع جديد قبل مراجعته.

## قواعد البيانات والمؤشرات

- «تمت المعالجة» مغلق، ويُستبعد من المفتوح والأعمار.
- الداخل في مشروع جارٍ بحدود معتمدة يرتبط بمقاول المشروع ومدير NWC للمتابعة.
- الخارج المؤكد من اختصاص الصيانة؛ نقص المرجع أو الإحداثيات ليس خارجًا مؤكدًا.
- شارت «تحت المعالجة» يشمل حالة المقاول والجهة المتعدية؛ «لدى المقاول» جزء منه وليس عددًا إضافيًا.
- الفلاتر مشتركة بين الشارتات والجدول والخريطة والتصدير. الحالات التي لا تملك مديرًا مرتبطًا تبقى منفصلة.

خلفية الشوارع تستخدم OpenStreetMap عبر الإنترنت وفق [سياسة الخدمة](https://operations.osmfoundation.org/policies/tiles/). لا يوفر التطبيق تنزيلًا جماعيًا للبلاطات.

## التحقق والنسخ الاحتياطي

```text
npm run lint
npm --prefix apps/web run typecheck
npm test
npm run build
npm run backup
```

اختبارات PostGIS تحتاج `POSTGIS_URL` صالحًا. اختبارات المتصفح تستخدم المجلد المعزول `nwc-repair-e2e` وبيانات اصطناعية؛ راجع `apps/web/scripts/testing/setup-e2e.ts` و`playwright.config.ts`.

النسخة الحالية تشغيل محلي وليست نشرًا عامًا. ترحيل كل الجداول إلى PostgreSQL وتطبيق RLS وتجهيز HTTPS والنسخ الاحتياطي الخارجي يحتاج إعدادًا مستقلًا. دور مدير المشروع لا يحصل على وصول قبل تهيئة نطاق مشاريعه. رفع المستودع إلى GitHub وحده لا يشغّل Next.js أو قاعدة البيانات ولا يحول التطبيق إلى GitHub Pages.
